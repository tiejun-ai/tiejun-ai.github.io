    Meta HSTU: Scaling Recommendation to Trillion Parameters — My Explanation and Thoughts

    September 20, 2026

    Understanding Meta’s HSTU and Generative Recommenders — how ranking and retrieval become sequential transduction, why pointwise attention fits user actions, and how generative training, stochastic length, and M-FALCON make trillion-parameter recommendation practical.

    Paper: Actions Speak Louder than Words: Trillion-Parameter Sequential Transducers for Generative Recommendations (Zhai et al., Meta, ICML 2024)

    Code: facebookresearch/generative-recommenders

    TL;DR#

    Traditional Deep Learning Recommendation Models (DLRMs) often scale poorly with increasing compute and model size. Can recommender models benefit from the same scaling behavior seen in LLMs?

    This paper replaces the traditional DLRM paradigm with a Generative Recommender (GR) built around three key ideas:

    • Represent heterogeneous features as one sequence. Merge features into one sequence, then reformulate retrieval and ranking as sequential transduction tasks.
    • Make long user sequences affordable. Design HSTU as an efficient sequence-modeling layer and combine it with Stochastic Length and fused GPU kernels.
    • Amortize inference across ranking candidates. M-FALCON algorithm divides ranking candidates into microbatches, uses a carefully designed causal attention mask to score them independently in parallel, and reuses cached user-history computation across microbatches.

    The production system scales to 1.5 trillion total parameters, including embedding tables, and improves the main online ranking metric by 12.4%. HSTU-based GRs outperform traditional DLRMs in industrial evaluations, while HSTU outperforms Transformer-based recommenders on public benchmarks. At sequence length 8,192, HSTU is reported to be 5.3x–15.2x faster than FlashAttention2-based Transformers.

    Importantly, the paper demonstrates a scaling law for recommendation: the quality of HSTU-based Generative Recommenders improves predictably as model size and training compute scale up, while traditional DLRMs plateau.

    Problem: Scaling Beyond Traditional DLRMs#

    LLMs have achieved great success via scaling laws. Can recommendation systems enjoy similar scaling success?

    Inspired by LLM’s transformer based sequence modeling, Generative Recommendendation represents user as an action sequence, and it has been a promising new direction to scale up recommendation models. The paper identifies three obstacles that a scalable solution must overcome:

    1. Heterogeneous features have no obvious sequence structure. A DLRM combines item interactions with creator and user IDs, cross features, counters, ratios, and other signals. How to model all those features into a unified sequence model?
    2. The vocabulary is enormous and constantly changing. New items and creators arrive continuously, yielding billions of possible IDs rather than an LLM’s comparatively small, fixed token vocabulary. How to model sequence effectively over such an enormous vocabulary?
    3. The volume of actions makes naive sequence modeling too expensive. Large platforms process billions of user actions daily, and user histories can be extremely long. Training on each impression would repeatedly encode overlapping histories; scoring each candidate separately would repeat much of the same work at inference time.

    The paper’s proposed change: unify suitable features into an event sequence, then use a repeatable HSTU block to model them. (Diagram created for this blog, based on Figures 2 and 3 of the paper.)

    Method Explained#

    Unify heterogeneous features into one sequence#

    Let Φᵢ be the item shown at step i, and let aᵢ be the user’s response: click, like, skip, completion, share, and so on. The core history becomes:

    Φ₀, a₀, Φ₁, a₁, ... , Φₙ₋₁, aₙ₋₁

    The paper handles the rest of the traditional feature space in two ways:

    • Categorical features become events. Start with the longest user interaction stream, then merge in slower-changing signals such as followed creators, demographics, languages, and location changes. Repeated values are compressed by retaining only the first event in a consecutive segment.
    • Numerical features become learned computation. A feature such as “historical CTR on this topic” is an aggregation over categorical events (e.g. Clicks) already present in the sequence. Such features are removed and expected to be inferred from the sequence. As sequence length and model capacity grow, the sequence should contain enough information to approximate more of the original DLRM feature space.

    Formulate ranking and retrieval as sequential transduction#

    Sequential transduction is a seq2seq prediction problem: given an input sequence, predicts the output sequence. HSTU formulates ranking and retrieval as follows:

    TaskInput sequence (x)Output sequence (y)
    RankingΦ₀, a₀, Φ₁, a₁, …, Φₙ₋₁, aₙ₋₁a₀, ∅, a₁, ∅, …, aₙ₋₁, ∅
    Retrieval(Φ₀, a₀), (Φ₁, a₁), …, (Φₙ₋₁, aₙ₋₁)Φ′₁, Φ′₂, …, Φ′ₙ₋₁, ∅

    Table 1, adapted from the paper. Φᵢ is an item, aᵢ is the user’s action, and ∅ means there is no prediction target at that position. For retrieval, Φ′ᵢ = Φᵢ when aᵢ is positive; otherwise Φ′ᵢ = ∅. Other categorical features are omitted here for clarity.

    For example, suppose a user likes hiking video A, skips cooking video B, and then shares camping video C. Each task maps a complete input sequence x to an aligned target sequence y; each target uses only the input prefix up to its position.

    Retrieval uses completed (item, action) pairs to predict next retrieval item target:

    position: 0           1           2
x:        (A, like)   (B, skip)   (C, share)
y:        ∅           C           ∅

    The first target is ∅ because the next video, B, was skipped: that position contributes no retrieval loss. The second target is C because the user shared it.

    Retrieval supervises positive next-item targets; skipped items remain in the input history. (Diagram created for this blog.)

    Ranking interleaves items and actions to predict the user’s action on each candidate item:

    position: 0     1     2     3     4      5
x:        A     like  B     skip  C      share
y:        like  ∅     skip  ∅     share  ∅

    Here the model predicts like from A, skip from the history through B, and share from the history through C. In practice, a small neural network transforms the model output at each item position into multi-task ranking predictions.

    Ranking includes each candidate item before predicting its action; action-token positions have no target. (Diagram created for this blog.)

    HSTU: Efficient Encoder over Sequence#

    HSTU (Hierarchical Sequential Transduction Units) keeps a standard Transformer’s core idea: use attention to transform an input sequence of embeddings into an output sequence. For comparison, here is the scaled dot-product attention operation from the original Transformer paper:

    Figure 2 (left), Scaled Dot-Product Attention, from “Attention Is All You Need”.

    Equation (1) in that paper defines the operation:

    Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V

    One HSTU layer is:

    U, V, Q, K = split(SiLU(W₁X + b₁))
A          = SiLU(QKᵀ + relative_position_and_time_bias)
Y          = W₂(LayerNorm(A V) ⊙ U) + b₂

    The three HSTU sublayers (Diagram created for this blog, based on Equations 1-3.)

    Compared with a standard causal Transformer block:

    StageTransformer blockHSTU block
    ProjectionProduces queries Q, keys K, and values V.A fused projection produces Q, K, V, and an additional gate U.
    AttentionApplies softmax to each query’s scores, so the attention weights sum to one across visible positions.Applies SiLU to each score independently, then sums the weighted values and applies LayerNorm. Its scores also include relative position and time bias.
    After attentionApplies an output projection and a separate position-wise feedforward network.Multiplies the normalized, pooled history by U, then applies one output projection; the gate supplies feature interaction without that separate feedforward network.

    Both blocks use causal masking and residual connections.

    Why remove softmax?#

    Standard attention normalizes each query’s scores across the entire sequence with softmax. HSTU applies SiLU independently to every QKᵀ + bias score and aggregates the resulting weighted values without sequence-wide normalization.

    The authors give two recommendation-specific motivations:

    • Intensity matters. Ten related historical actions can be stronger evidence than one. Softmax forces attention weights to sum to one, making the magnitude of that evidence harder to retain.
    • The vocabulary is non-stationary. New items continuously enter the system, so the noise and composition of a user’s sequence change over time. The paper finds pointwise attention more suitable for this streaming setting.

    Because an unnormalized sum can vary sharply with sequence length, HSTU applies LayerNorm immediately after A * V.

    Why the U gate?#

    Feature Interaction is the most critical part of DLRMs. For similar benefits, the elementwise product LayerNorm(A V) ⊙ U in HSTU enables attention pooled features to directly “interact” with other features.

    Generative Training#

    Traditional impression-level training emits one example per impression. For user i with a history of length nᵢ, this repeatedly encodes overlapping prefixes of lengths 1 through nᵢ. The attention work accumulates as (1² + 2² + ... + nᵢ²)d = O(nᵢ³d), while pointwise feedforward layers add O(nᵢ²d²). Let N be the maximum history length across users; the paper summarizes the encoder computation cost as:

    O(N³d + N²d²)

    Generative training instead emits a sequence-level example, applies causal masking, and computes losses at many valid positions in one pass.

    Sampling user i at a rate proportional to 1/nᵢ—which the paper approximates by emitting an example at the end of a request or session—reduces the encoder computation cost to:

    O(N²d + Nd²)

    This is one of the key ideas for reducing traing cost.

    Making Long Histories Affordable#

    The paper also discussed several important optimization to make training and inference over long user sequence affordable.

    Ragged attention#

    User histories are highly uneven. Padding every user to the maximum length wastes most attention work. HSTU uses custom kernels that operate on ragged sequences and fuse the two attention matrix multiplications as grouped GEMMs. The paper attributes 2x-5x throughput gains to this alone.

    Stochastic Length#

    Attention gets expensive as a history grows: doubling its length roughly quadruples the attention work. Yet a long history often contains repeated signals—for example, a user may watch many similar cooking videos over several weeks. Stochastic Length (SL) takes advantage of this redundancy during training. It leaves shorter histories intact; for sufficiently long ones, it sometimes trains on a sampled subsequence instead of processing every event.

    For example, with a maximum history length of 4,096 and α = 1.6, the paper’s SL rule reduces a 4,096-event history to 776 events on most training passes. Its preferred sampling method favors recent interactions but can retain older ones too.

    The sampling probabilities are chosen so expected attention-related cost scales as O(N^α d) for 1 < α ≤ 2, instead of O(N²d); smaller α saves more compute. The paper’s evaluation shows that SL has little adverse impact on model performance.

    Lower activation memory#

    Compared to standard Transformer, HSTU reduces the linear layers around attention, fuses projection, activation, normalization, dropout, and output operations, leading to much lower memory need.

    Atomic-ID embeddings remain enormous. The paper’s example - 10 billion IDs at embedding dimension 512 with Adam optimizer- would require about 60 TB for storing embeddings and optimizer state in fp32. So it uses row-wise AdamW and moves optimizer state to DRAM, reducing high-bandwidth-memory significantly.

    M-FALCON: Score Many Candidates Against One User History#

    If there are m candidates and the same user history of length n, the naive ranking model runs inference with target-aware attention independently for every candidate.

    M-FALCON - Microbatched-Fast Attention Leveraging Cacheable OperatioNs - appends a microbatch of candidates after one shared user history sequence. It adjusts the attention mask and relative position/time biases so each candidate can attend to the history but not to other candidates. One forward pass scores the candidates in that microbatch, producing the same results as scoring each of them separately.

    M-FALCON changes execution, not model semantics: candidates see the history but not one another. (Diagram created for this blog, based on Figure 11 and Algorithm 1.)

    The first microbatch produces a cache of the history’s keys and values. Later microbatches reuse them via KV Caching and compute only the candidate-side projections and attention. In the paper’s analysis, batching changes the repeated attention cost from O(mn²d) to O((n + bₘ)²d), which is approximately O(n²d) when the microbatch size bₘ is small relative to the history.

    This important optimization is not HSTU-specific, and it can apply to other causal self-attention models doing target-aware scoring.

    Efficiency and scaling#

    In the paper’s encoder-level comparison on NVIDIA H100 GPUs, HSTU achieves up to 15.2x higher training throughput and 5.6x higher inference throughput than a FlashAttention2-based Transformer.

    The paper’s most important result: GR quality continues to improve approximately as a scaling law of compute, while DLRM quality plateaus. Higher Hit Rate and lower NE are better. (Figure 7 from the paper, Zhai et al., 2024.)

    The largest deployed GR model has 1.5 trillion parameters, while the performance of DLRMs saturate at about 200 billion parameters.

    My Thoughts#

    Lessons from Meta HSTU#

    The Meta HSTU paper combines several ideas that make sequence-based recommendation models practical at production scale. Many may also apply to other generative recommenders:

    • Unifying Features as Sequence
    • Formulate Retrieval and Ranking as Seq2Seq Models
    • Generative Training
    • Stochastic Length
    • Design Efficient Attention Layer (e.g. HSTU)
    • Smart M-FALCON algorithm to compute attention over batched candidates

    Open Questions#

    The paper addresses compute and memory bottlenecks while retaining a large, dynamic vocabulary of atomic item IDs. Those IDs still require large embedding tables and enough interaction data to learn useful representations, especially for new items. Many recent generative recommenders (e.g. TIGER and PLUM) instead use Semantic IDs: short code sequences derived from item-content embeddings. Their smaller token vocabularies may reduce embedding-memory pressure and help with cold start. HSTU’s long-history modeling might be combined with Semantic IDs to make an even more powerful and scalable recommendation system.

    Big picture#

    The paper is important because it develops practical and effective methods for sequence-based generative recommendation and it is one of the pioneering generative recommenders successfully deployed at ultra large production scale. More importantly, its experiments show evidence supporting the “Scaling Law” for Recommender Systems. This is a very exciting result as it means generative recommendation might be a promising approach to achieve potentially huge recommendation quality improvement via training and model scale up.
